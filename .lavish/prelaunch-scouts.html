Launch blockers

1. locate() crashes on any repo with a CSS-module or JSON import

reproduced

buildGraph creates nodes only for .ts/.tsx/.js/.jsx, but tryPath returns a bare specifier when that exact key exists in repo.files. So an edge can point at a path with no node, and locate dereferences byPath[p].rel unguarded.

Harmless on the web and CLI paths — both filter to JS/TS before building the graph. But the Agent Run path ingests json|css|scss|md and calls the same functions on that map.

nodes: 1 edges: [{"from":"src/app/dashboard/page.tsx",
                  "to":"src/app/dashboard/Dashboard.module.css"}]
*** locate THREW: TypeError - Cannot read properties of undefined (reading 'rel')
Why it matters: the first invited alpha user who points a Run at a React repo using CSS Modules gets a hard failure. The raw error is never logged — only a failureKind — so you cannot diagnose it from production. Fix is one guard at src/lib/localizer.ts:315, or drop non-node edges in buildGraph.

2. A single failed Run blocks Agent Runs deployment-wide for an hour

verified

cancelled exists in RUN_STATUSES and canTransitionRun permits it, but nothing ever sets it — the [id] route has only approve and review subroutes, and the only cron is retention. There is no reaper and no self-service recovery.

If the workflow dies before the lease is released, the provider lease persists for 3600s while max_concurrent is 1. Capacity-rejected runs still burn daily quota, because the count happens before the insert and counts rows by created_at regardless of status.

Why it matters: blocker 1 fires on the first user's first Run, the lease is orphaned, and every other invited user gets capacity rejections for an hour while burning their daily allowance. The alpha is dead for a day and the logs say workflow_error. The state machine already permits cancel — the route is missing.

verified

Under ## Verification, directly beneath "GitHub CI runs lint, tests, CLI sync, type-checking, and a production build", the README says the historical benchmark "fails its launch gate if fix-file recall drops below 100%".

Why it matters: in that context a reader concludes the gate runs in CI. It does not. benchmarks/results.json is a checked-in artifact from one local run on 2026-08-04. This is the same class of problem as the R13 analytics claim the gate caught earlier — a verification claim that outruns the verification.

The security fork — only you can resolve this

/api/v1/locate has no repository-visibility check

verifiedneeds you

src/app/api/github/route.ts:210 refuses non-public repos explicitly. The public API route has no equivalent — its only related line is :81, if (info.status === 404) throw new Error("Repository not found or is private."). That catches a private repo only when the token cannot see it. It also attaches process.env.GITHUB_TOKEN at :23.

Separately, API-key minting requires only a Clerk session, while Agent Runs require the alpha allowlist. Anyone who signs up gets keys.

The fork: if GITHUB_TOKEN in Vercel production carries repo scope, any signup can read the full source of every private repo that token can see, packed into context, at 30 req/min — while your docs promise "public JavaScript and TypeScript repositories". If the token is unset, that exposure disappears and instead you inherit GitHub's unauthenticated 60 requests/hour per shared Vercel egress IP, against 8 API calls per repo load — so the importer 403s for everyone on launch day. Check which one you shipped before anything else.

Market: the pitch is aimed at the wrong buyer

The closest competitor is free, stronger, and an official Claude plugin

scout research

Serena — 27.9k stars, MIT, 30+ languages — does LSP-based symbol retrieval and explicitly sells "token-efficient". Locus parses imports with regex and scores files by matching task words against paths and source text. For TypeScript, compiler-grade symbol resolution is strictly more accurate. The "TypeScript accuracy" wedge is claimed against a tool that already has it, plus 30 other languages.

zilliztech/claude-context (12.4k stars) publishes the same 40% token claim, free. Nobody monetises token reduction as a SKU; the ones charging money — Cursor, Augment, Greptile — charge for accuracy and review outcomes.

The hosted product caps below where the problem starts

verified

MAX_FILES = 200 at src/app/api/github/route.ts:13, enforced at :238. Cursor's published measurements put retrieval benefit at 1,000+ files. Anyone trying it on a real codebase gets truncation, not a demo — and savedPct is computed against the truncated denominator.

Two arguments worth sitting with

scout research

A slice up front does not stop the agent grepping. It adds tokens unless the agent is told to trust the slice — and if it trusts a slice built by word-matching, the quality risk moves to you. Your benchmark measures whether fix files were included, not whether an agent finished with fewer total tokens.

Anthropic's context editing cut tokens 84% while improving task performance 29–39%, free, attacking accumulated history rather than initial file selection. Bigger number, aimed at the part of the bill that dominates.

The counterweight, and it is real: ContextBench (1,136 tasks, 66 repos, human-annotated gold contexts) finds all frontier models over-retrieve, 0.35 F1 at line level, up to 43% evidence drop. So agentic search is measurably wasteful. That is the strongest evidence in your favour and it comes from a neutral party.

The wedge the scout would bet on

scout research

Not "smaller prompts for developers." The deterministic, auditable context-admission layer for unattended agent runs under a token budget — CI bots, bulk migrations, PR agents — where determinism is a requirement rather than a preference, and where "here are the included paths, the excluded paths, and the reason" is a governance artifact that embeddings structurally cannot produce.

Enterprise token caps became real this year: Uber burned its 2026 AI budget by April across ~5,000 engineers and imposed a per-tool cap; Microsoft pulled Claude Code licences from a division at ~$2,000/engineer/month. That is a budget that exists, with an owner. Serena and claude-context are not positioned there — they are interactive developer ergonomics.

Note the alignment: Anthropic's own stated reasons for dropping RAG were staleness, privacy, and reliability — which is your determinism pitch, not against it.
